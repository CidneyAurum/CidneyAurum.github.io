## 本轮整页背景歌词本机验收

本轮目标为整个页面的透明背景歌词：直接挂在 body 下、fixed 覆盖视口，不占内容布局。设计行为对照桌面项目的 [歌词窗口](https://github.com/YouRanCoder/LimbusLyricSimulator/blob/main/ui/lyric_window.py) 和 [逐字及残影绘制](https://github.com/YouRanCoder/LimbusLyricSimulator/blob/main/ui/fading_line.py)，站点布局参考 [星梦幽灵的小窝](https://xmyl-153.github.io/xingmengyouling-blog/)。Web 代码独立实现，没有复制 GPL-3.0 桌面代码。

tests/test_lyric_stage.py 的 **15 项背景用例全部通过**，使用真实 HTMLAudio 解码 20 秒生成 WAV，由实际播放时间、暂停、seek 和原生 ended/循环事件驱动歌词；音乐和歌词 HTTP 响应使用隔离夹具，没有手工派发音乐事件冒充播放。最终 CI 为 **83 项 Node + 127 项 Python/Chromium = 210 项，全部通过**；Python 套件耗时 65.756 秒，记录为 background-ci-final.log。CSS 修复前的 209 项本机结果仅作较早基线。

- **透明覆盖与前景操作通过。** 背景节点为 body 直属，fixed 覆盖视口且不撑开布局；实际点击导航与播放器、滚动页面及键盘切换均正常，没有歌词模态框、inert 或滚动锁。透明层不接管指针输入。
- **专用开关通过。** 默认随歌曲启用，首页音乐卡「背景演出」与全局播放器「演」关闭或恢复同一背景效果，不暂停音乐。原「词」按钮继续控制可点击跳播的歌词列表，两者独立；禁止 localStorage 访问时仍可操作。旧面板 lyric_stage_effects=0 不会关闭新背景动效。
- **原生时间同步通过。** 自然播放、暂停恢复、前后 seek、同曲重播及原生单曲循环重新定位正确；暂停时当前句完整可读且停止动画，恢复不会重播当前句的揭示。同时间戳原文/译文成组，换曲加载立即清空旧句，失败保持背景为空并可从音乐卡重试。
- **随机落点与排字通过。** 歌曲与时间戳决定稳定随机落点和约 ±10° 基线，新句候选避开残影，同一句不逐帧重抽位置。独立观察四个自然 cue 得到四个不同坐标；行与字形反向角抵消，字形正立，逐字揭示和持续轻抖同时生效。
- **残影通过。** 旧句保持原坐标和角度；独立观察约 300ms 时上浮约 9.6px 且透明度降低，约 680ms 后移除，对应 660ms 上浮约 22px 的 CSS 淡出动画。seek、暂停和换歌不会残留旧句。
- **手机长句与减弱动效通过。** 自动回归覆盖 390×700 长双语及 844×390 旋转边界；独立浏览器另以 72 字 CJK 原文和 156 字无空格 Latin 译文检查 320×480、320×568、375×667、390×844 与 844×390，所有字框都在视口内。系统 reduced motion 及关闭动效时保持静态可读，音频正常推进。
- **PJAX 生命周期通过。** 首页到手记再返回，保留同一背景层和原生音频、一个活动订阅，不重复创建播放器；独立浏览器确认换页时当前 cue 节点也保持。导航、文章模板与知识索引继续不提供旧实验室入口。
- **小数逐字延迟回归通过。** 17 字（含空格）、5.75 秒句间隔产生 102.941176ms/字；原生音频自然进入首句，末字延迟前 opacity=0，播放至 2.05 秒时全 17 字 opacity=1，不通过 seek 跳过动画。仅在浏览器内注入旧 steps(1,end) CSS 的反向验证会失败，前 10 字可见、后 7 字仍为 0；修复后的 CSS 通过同一用例。
