《如何发布一篇新文章 / 新照片》

🗓 2026-08-29 📝 约 614 字 · 2 分钟 👁 … 次围观 # 指南

发文、发图可以按顺手程度选一种。本文操作说明更新于 2026-10-25。

方式零：写作台（最简单，推荐）

打开网站的 ✍️ 写作台：

  • 发文：填标题 → 写 Markdown（右边实时预览）→ 点「一键发布到 GitHub」。文字草稿会自动保存在当前浏览器；文件重名时会停止写入，避免覆盖旧文章。
  • 发图：把图片拖进虚线框（可多选）→ 每张图可以改标题 → 点「全部上传」。文件名会自动避免重名；部分上传失败时，剩余图片保留在队列里。

提交成功后，Actions 会检查、构建并部署。只有对应提交的 Pages 部署成功，才能确认上线；完成时间取决于队列、检查与部署进度。首次启用新版流程前，需要在仓库 Settings → Pages 中将来源设为 GitHub Actions。

首次使用需要到写作台的「设置」页粘贴一次 GitHub 令牌（Fine-grained PAT，只授权本仓库的 Contents: Read and write），之后浏览器会记住。

方式一：本地一条命令

在 _posts/ 里写一个 xxx.md（格式见下），然后：

python tools/build.py
git add -A && git commit -m "发布新文章" && git push

方式二：GitHub 网页直接写

仓库 → _posts/ → Add file → Create new file → 文件名用英文（如 my-first-note.md）→ 写完提交即可。

Markdown 文件格式

---
title: 文章标题
date: 2026-09-01
tags: 日常, 笔记
emoji: 🪐
summary: 一句话摘要
---

正文用 Markdown 写。

其实只有标题是必须的：不写日期默认今天，不写摘要会自动截取正文第一段，标签/emoji/封面都能省略。

常用语法：## 标题、**加粗**、`代码`、> 引用、[链接](网址)、![图](图片路径)、代码块用三个反引号包裹。

发照片的补充说明

  • 图片标题默认取文件名，想改可以在写作台上传时填写
  • 写作台上传时自动添加年月；直接上传无日期文件时，构建会尽量取首次提交年月，无法确定则显示 MEMORY
  • 封面进阶：front-matter 里写 cover: assets/xxx.jpg 可以用图片当文章封面

和 Miku 一起起稿

写作台的「Miku 的写作便签」可以按当前正文拟标题、提炼摘要，或润色选中的一段。先写一点正文，再点对应按钮；建议会展示在独立的框里，由你决定是否应用，也可以复制或撤销。

建议不会自动覆盖新编辑的内容，也不会自动发布。AI 服务接通后才会进行模型请求；未接通时会给出明确提示。
